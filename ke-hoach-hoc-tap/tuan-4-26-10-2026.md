## Ngày 22: 26/10/2026 (Thứ 2) - Giao thức HTTP
* **Sáng (Học gì):** 
  * Cấu trúc của một URL, Endpoint.
  * Phân biệt các HTTP Methods chính: `GET` (Lấy data) vs `POST` (Gửi data đi).
  * Ý nghĩa các HTTP Status Codes thường gặp: `200` (OK), `400` (Bad Request), `404` (Not Found), `429` (Too Many Requests), `500` (Internal Error).
* **Chiều (Thực hành gì):** 
  * Cài đặt phần mềm Postman (hoặc Insomnia).
  * Lên mạng tìm một Public API miễn phí (ví dụ: JSONPlaceholder, PokeAPI, hoặc Weather API). Dùng Postman gọi thử lệnh GET và POST để xem dữ liệu JSON trả về.
* **Tối (Nộp gì):** 
  * Bảng tổng hợp ý nghĩa các status code.
* **Đạt khi nào (PASS):** 
  * Nhìn vào mã lỗi (vd: `400` vs `500`), giải thích được lỗi do người dùng (Client) gửi sai hay do server code "ngu".

## Ngày 23: 27/10/2026 (Thứ 3) - Requests & Xử lý Timeout/Retry
* **Sáng (Học gì):** 
  * Cách gọi API từ trong code Python thay vì dùng Postman (sử dụng thư viện `requests` hoặc `httpx`).
  * Tầm quan trọng của `Timeout` (Không để hệ thống chờ vô tận) và `Retry` (Thử lại khi mạng chập chờn).
* **Chiều (Thực hành gì):** 
  * Viết script Python dùng `requests.get()` để gọi một API lấy dữ liệu thời tiết.
  * Tự đặt `timeout=0.001` để ép chương trình quăng lỗi Timeout, sau đó dùng khối lệnh `try-except` (học ở Tuần 1) để bắt lỗi, in ra thông báo thân thiện.
  * Cài thư viện `tenacity` để cấu hình tự động gọi lại (retry) 3 lần nếu gọi API thất bại.
* **Tối (Nộp gì):** 
  * Code gọi API có xử lý timeout/retry.
* **Đạt khi nào (PASS):** 
  * Script gọi API không bao giờ bị "treo", luôn có fallback an toàn khi rớt mạng.

## Ngày 24: 28/10/2026 (Thứ 4) - Khởi tạo Web Server (FastAPI)
* **Sáng (Học gì):** 
  * `FastAPI` là gì? Tại sao nó lại là "tiêu chuẩn vàng" cho các dự án AI hiện nay.
  * Cài đặt `fastapi` và `uvicorn` (server để chạy code).
* **Chiều (Thực hành gì):** 
  * Viết file `main.py` đầu tiên. Mở port `8000`.
  * Viết một endpoint `GET /health` đơn giản trả về `{"status": "ok"}`.
  * Mở trình duyệt truy cập `http://localhost:8000/docs` để xem giao diện Swagger xịn xò mà FastAPI tự sinh ra.
* **Tối (Nộp gì):** 
  * File `main.py` cơ bản.
* **Đạt khi nào (PASS):** 
  * Chạy lệnh `uvicorn main:app --reload` thành công. Gọi từ trình duyệt ra được chữ OK.

## Ngày 25: 29/10/2026 (Thứ 5) - Pydantic trong FastAPI
* **Sáng (Học gì):** 
  * Cách FastAPI dùng `Pydantic BaseModel` (học ở Tuần 1) để tự động validate Body của request `POST`.
* **Chiều (Thực hành gì):** 
  * Tạo endpoint `POST /search`. Khai báo `SearchRequest` model bắt buộc người dùng truyền vào `query` (chuỗi dài tối thiểu 5 ký tự) và `top_k` (số nguyên từ 1 đến 10).
  * Dùng Postman gọi API này với `top_k = "mười"`. Xem FastAPI tự động chửi (văng lỗi 422 Unprocessable Entity) như thế nào.
* **Tối (Nộp gì):** 
  * Code endpoint POST có validate Pydantic.
* **Đạt khi nào (PASS):** 
  * Không cần viết dòng `if` nào mà API vẫn bắt lỗi người dùng nhập sai một cách hoàn hảo.

## Ngày 26: 30/10/2026 (Thứ 6) - Biến môi trường (.env) & Kiến trúc
* **Sáng (Học gì):** 
  * Tại sao KHÔNG bao giờ được hardcode mật khẩu, API key thẳng vào file `.py`?
  * Thư viện `python-dotenv`.
* **Chiều (Thực hành gì):** 
  * Tạo file `.env` chứa `SECRET_KEY=my_super_secret`. (Nhớ thêm `.env` vào file `.gitignore` để không push lên Github - cực kỳ quan trọng).
  * Sửa code `main.py` để load `SECRET_KEY` từ file `.env` lên và in ra thử.
* **Tối (Nộp gì):** 
  * Source code đã phân tách env.
* **Đạt khi nào (PASS):** 
  * Hiểu được quy trình bảo mật cơ bản khi deploy ứng dụng ra thực tế.
