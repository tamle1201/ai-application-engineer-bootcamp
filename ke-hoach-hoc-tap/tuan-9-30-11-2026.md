# KẾ HOẠCH HỌC TẬP CHI TIẾT - TUẦN 9
**Chủ đề:** Module Chuyên Sâu Khóa Luận: Tách Phát Biểu (Claim Extraction)
**Ngày bắt đầu:** Thứ 2, ngày 30/11/2026
**Mục tiêu tuần:** Bước chân vào lõi nghiên cứu. Bạn sẽ dùng LLM chia nhỏ 1 câu trả lời dài của RAG thành nhiều "phát biểu nguyên tử" (Atomic Claims) để dễ dàng kiểm chứng đúng sai cho từng vế (phục vụ vẽ Graph trực quan).

---
## Ngày 57: 30/11/2026 (Thứ 2) - Định nghĩa Atomic Claim
* **Sáng (Học gì):** 
  * "Phát biểu nguyên tử" (Atomic Claim) là gì?
  * Đọc bài báo FACTSCORE để hiểu cách giới nghiên cứu chia 1 đoạn văn dài thành các mảng Fact độc lập có thể kiểm chứng.
* **Chiều (Thực hành gì):** 
  * Lấy 10 đoạn trả lời của RAG Tuần 8.
  * Tự thực hành TÁCH TAY bằng não bộ ra giấy. 
  * (Ví dụ câu: "Sinh viên có GPA dưới 1.0 và nợ quá 15 tín chỉ sẽ bị đuổi học" -> Tách thành: [1] Sinh viên có GPA dưới 1.0 sẽ bị đuổi học. [2] Sinh viên nợ quá 15 tín chỉ sẽ bị đuổi học).
* **Tối (Nộp gì):** 
  * Danh sách 10 đoạn text kèm theo bản tách claim viết tay.
* **Đạt khi nào (PASS):** 
  * Hiểu rõ ranh giới của một phát biểu nguyên tử: Nó phải chứa đúng 1 mệnh đề thông tin độc lập.

## Ngày 58: 01/12/2026 (Thứ 3) - Prompt Engineering cho Extraction
* **Sáng (Học gì):** 
  * Viết System Prompt đóng vai một nhà phân tích ngữ nghĩa (Linguist Expert).
  * Ứng dụng kỹ thuật Few-Shot (Tuần 5) cực kỳ gắt gao ở đây. Đưa vào prompt 3 ví dụ bạn vừa tách tay hôm qua.
* **Chiều (Thực hành gì):** 
  * Dùng thư viện `instructor` (Pydantic Tuần 6) để ép LLM trả về đúng schema là `List[str]`. 
  * Truyền thử một đoạn văn bản vào Prompt, bắt LLM nhả ra chuỗi JSON array chứa các claims.
* **Tối (Nộp gì):** 
  * Script Extraction cơ bản kết hợp Pydantic.
* **Đạt khi nào (PASS):** 
  * Prompt xịn đến mức AI không bao giờ sinh ra dư chữ giải thích, chỉ nhả ra đúng 1 mảng các câu.

## Ngày 59: 02/12/2026 (Thứ 4) - Tích hợp Module Extraction vào Class
* **Sáng (Học gì):** 
  * Ôn lại cấu trúc Class, tổ chức Code thành một Module độc lập (VD: `ClaimExtractor`).
* **Chiều (Thực hành gì):** 
  * Đóng gói code Ngày 58 thành hàm `extract_claims(answer_text: str) -> List[str]`.
  * Chạy vòng lặp test tự động 20 câu trả lời. Ghi kết quả ra log file (JSON) để dễ đọc.
* **Tối (Nộp gì):** 
  * File log JSON chứa toàn bộ kết quả extract từ AI.
* **Đạt khi nào (PASS):** 
  * Chạy file không bị lỗi Pydantic Validation error, kết quả ổn định.

## Ngày 60: 03/12/2026 (Thứ 5) - Giải quyết Lỗi Mất Ngữ Cảnh (Pronoun Coreference)
* **Sáng (Học gì):** 
  * Lỗi phổ biến chết người trong NLP: "Pronoun Coreference" (Đại từ bị mất liên kết).
  * Nếu tách câu: "Nó bị đuổi học" ra khỏi đoạn văn, ta sẽ không biết "Nó" là ai. Điều này làm cho Claim không thể verify được ở bước sau!
* **Chiều (Thực hành gì):** 
  * Bổ sung quy tắc cực mạnh vào System Prompt: "TẤT CẢ đại từ (nó, họ, sinh viên đó, khoản này) bắt buộc phải được thay thế bằng danh từ đầy đủ mang ý nghĩa nguyên bản".
  * Test lại hệ thống với các đoạn văn dùng nhiều đại từ.
* **Tối (Nộp gì):** 
  * Prompt phiên bản Anti-Pronoun.
* **Đạt khi nào (PASS):** 
  * Nhìn vào 1 claim riêng lẻ, không cần đọc câu trước mà người đọc vẫn hiểu chính xác chủ thể là ai/cái gì.

## Ngày 61: 04/12/2026 (Thứ 6) - Cấu trúc lại Node Data cho Frontend
* **Sáng (Học gì):** 
  * Đồ thị Frontend (Obsidian-style) cần Nodes (Điểm) và Edges (Đường nối).
  * Chuẩn bị dữ liệu để map 1 Câu Trả Lời (Parent Node) ra nhiều Claims (Child Nodes).
* **Chiều (Thực hành gì):** 
  * Sửa class `RAGService` để API trả về dữ liệu đa tầng. 
  * Thay vì chỉ trả `{ "answer": "..." }`, nay sẽ trả về `{ "answer": "...", "claims": [ { "id": "c1", "text": "..." }, { "id": "c2", "text": "..." } ] }`.
* **Tối (Nộp gì):** 
  * Backend API cập nhật Data Model.
* **Đạt khi nào (PASS):** 
  * API response trả về chuẩn cấu trúc cây thư mục.

## Ngày 62: 05/12/2026 (Thứ 7) - Gate W9: Ground Truth & Evaluation
* **Sáng (Học gì):** 
  * Kỹ thuật "LLM as a Judge" (Dùng LLM mạnh như GPT-4 để chấm điểm output của LLM yếu hơn hoặc hệ thống nội bộ).
* **Chiều (Thực hành gì):** 
  * **Gate W9 Challenge:** Xây dựng tập "Ground Truth" nhỏ: Tự tay viết 50 mảng Claims chuẩn xác cho 50 đoạn text. 
  * Chạy Module `ClaimExtractor` qua 50 đoạn text đó. Đưa output và Ground truth cho GPT-4 làm Giám khảo so sánh, chấm điểm trùng khớp.
* **Tối (Nộp gì):** 
  * Báo cáo đánh giá độ chính xác (Accuracy score) của module Extract.
* **Đạt khi nào (PASS):** 
  * Module Tách ý chạy trơn tru, không bỏ sót ý chính trong văn bản, và không giữ lại các đại từ mơ hồ.
